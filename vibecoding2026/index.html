Section 1

What is vibe coding?

You describe the goal in natural language. An AI coding agent edits files, runs commands, and iterates with you inside a real project.

  • Not “ask ChatGPT → copy → paste → hope”
  • The agent can see your folder, create files, and fix errors
  • You stay in charge: accept, reject, refine the prompt

Key distinction

Chat mode vs IDE / work mode

Chat mode (common)

  • Conversation in a browser or app
  • You copy code into files yourself
  • Weak project context
  • Easy for Q&A; hard for shipping

IDE / work mode

  • Agent works inside your project
  • Creates / edits files directly
  • Can run terminal commands
  • Built for finishing a working app
Today we practice IDE / work mode.

Why the difference matters

Section 4 · Task 1

Download financial data

Use Python with yfinance (or akshare) to download AAPL daily prices into a clean CSV.

yfinance

Convenient for US tickers such as AAPL.

akshare

Useful alternative, especially for China-market data later.

Success look

First row = column names. Data rows start immediately under the header. No junk title rows.

Sample prompt

Download AAPL data

In this folder, create a Python script download_aapl.py that:
1) Uses yfinance to download AAPL daily OHLCV for the past 2 years
2) Saves the result as data/aapl.csv
3) Makes sure the CSV has a normal header row (column names) as the first row
4) Includes Date as a column (not only as an unnamed index)
5) Prints the first 5 rows and the column names after saving

If yfinance is not installed, install it in the current environment.
Then run the script and fix any errors until the CSV exists.

Sample prompt

Validate the CSV format

Open data/aapl.csv and verify:
1) Row 1 is column names only
2) Row 2 onward contains values aligned under those columns
3) There is a Date column and at least Close (or Adj Close)
4) No blank header, no multi-line title block, no JSON dumped into one cell

If anything is wrong, fix the download script and regenerate the CSV.
Finally show me: column names, number of rows, and the first 3 data rows.
Do not jump to the web app until this check passes.

Section 5 · Task 2

One HTML file web app

Build a vanilla web app in a single index.html file for simple analysis of the downloaded data.

Single file No build step Submit this HTML
  • Upload / load the CSV in the browser
  • Show basic stats (rows, date range, mean / min / max of Close)
  • Optional: a simple chart

Design choice

Why a single HTML file?

Easy to submit

One file to collect and grade.

Easy to host

GitHub Pages loves static files.

Easy to debug

No React/Vite setup today.

You may embed CSS and JavaScript inside the same HTML file. External CDNs for a chart library are OK if needed.

Sample prompt

Build the web app

Create a single file named index.html (all CSS/JS inside this file) that:
1) Lets the user upload a CSV (default expectation: AAPL OHLCV with Date and Close)
2) Parses the CSV in the browser
3) Shows: number of rows, date range, mean/min/max of Close
4) Draws a simple line chart of Close vs Date
5) Has clear error messages if the file is missing Date or Close
6) Works by double-clicking the HTML file or via a local static server
7) Uses no backend and no API keys

Keep the UI clean and beginner-friendly. After generating the file, tell me how to test it with data/aapl.csv.

Quality bar

What “done” looks like

  • Only one HTML file is required for submission
  • Uploading aapl.csv shows numbers that match Python’s quick summary
  • Chart (if included) updates after upload
  • Someone else can open the file without installing Python

Optional stretch

Add a ticker label, moving average toggle, or a second uploaded series — only after the basic version works.

Manual click

Enable GitHub Pages

  1. Open the repo on GitHub
  2. Settings → Pages
  3. Build and deployment → Source: Deploy from a branch
  4. Branch: main (or master), folder: / (root)
  5. Save, wait 1–2 minutes, open the URL

Appendix A

Monitor visits with Google Sheets

The page sends anonymous events to a Google Apps Script, which appends rows to a Sheet.

1 · Sheet

Create a Google Sheet as your log table.

2 · Apps Script

A tiny doPost web app writes each visit/event.

3 · Web app

Your HTML/JS posts JSON when a page opens.

Appendix A

What to log (and what not to)

OK (anonymous)

  • timestamp
  • session id (random)
  • page / scene name
  • course / project label

Avoid

  • student name / SID
  • emails
  • typed answers with personal data
  • API keys
This is not for surveillance of individuals.

Appendix A

Setup sketch

  1. Create a Google Sheet → Extensions → Apps Script
  2. Paste a doPost script that appends JSON fields to a usage_log tab
  3. Deploy → Web app → Who has access: Anyone
  4. Copy the web app URL into your front-end as the log endpoint
  5. On page load, fetch(url, { method: "POST", body: JSON.stringify(event) })

Ask your IDE

Add anonymous visit logging to this static HTML app.
Post only timestamp, random sessionId, and page title to a Google Apps Script URL placeholder.
Do not collect names or personal data. Fail silently if the network request fails.

Appendix B

Start local with free CLōD

  1. Register at https://app.clod.io
  2. Create an API key
  3. Store it in .env / .env.local — never in the HTML you publish
  4. Call the model from a small local server function
CLōD is excellent for local practice. On public cloud hosts it is often blocked (e.g. Cloudflare challenges), so do not plan on CLōD alone for a public AI demo.

Appendix B · precise version

GitHub Pages vs AI APIs

ClaimMore accurate version
“CLōD is only for local apps” Best treated as local-first. Public serverless hosts often cannot call it reliably.
“Online AI needs a paid API” Public AI usually needs a cloud API that servers can call (DeepSeek is a common low-cost example). Free tiers may exist elsewhere, but keys still must stay off the public HTML.
“AI can’t work on GitHub” GitHub Pages is static hosting: great for HTML/CSS/JS files, but no server-side functions to hide keys. You can call an API from the browser only if you expose a key (unsafe) or ask each user for their own key.
“Need Vercel” Need some host with server/serverless functions (Vercel, Netlify, Cloudflare Workers, Render, …) to proxy AI requests safely. Vercel is one popular choice.

Appendix B

Public AI path (sketch)

DeepSeek (example)

  • Cloud API suitable for server calls
  • Keep DEEPSEEK_API_KEY in host env vars
  • Set usage limits; public chat can be abused

Vercel (example host)

  • Connect the GitHub repo
  • Add a serverless function e.g. /api/chat
  • Front end talks to your function, not directly to the model with your key

Safety red line

Never paste API keys into GitHub Pages HTML. Treat keys like passwords.
